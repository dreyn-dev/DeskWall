# 0011. Обои на каждом мониторе: окно на монитор, своя тема у каждого

- Дата: 2026-11-16
- Статус: принято
- Кто решил: Mark (попросил тему для второго монитора), реализация Claude

## Контекст

Обои покрывали только основной монитор, на втором оставались обычные обои Windows. У Mark два
монитора, он хочет выбрать тему для второго.

## Решение

- Одно окно обоев на монитор. Статичное окно `wallpaper` всегда на основном мониторе, для
  остальных хост на лету создаёт окна `wallpaper-<id>` (`id` — имя устройства Windows без `\\.\`,
  например `DISPLAY2`) со страницей `wallpaper.html?screen=<id>`.
- Наблюдатель раз в 250 мс перечисляет мониторы (`EnumDisplayMonitors`); если набор, положение
  или основной монитор поменялись, или монитор выключен в настройках, окна добавляются,
  закрываются и прикрепляются заново.
- Настройка `screenThemes`: для каждого дополнительного монитора `same` (как на основном, не
  хранится), id темы или `off` (обычные обои Windows, окна нет). Параметры тем общие.
- Иконки читаются один раз и раздаются окнам: иконка принадлежит монитору, где её центр.
  Курсор уходит окну монитора под ним. Пауза «полный экран» — только для монитора, где
  развернуто окно или запущена игра; презентация ставит на паузу все.

## Альтернативы

- Одно окно на весь виртуальный экран и несколько сцен в одном canvas: меньше окон WebView2, но
  движок пришлось бы переписать под несколько вьюпортов с разными темами, а мониторы с разным
  DPI в одном окне рисуются плохо.

## Последствия

- Каждый монитор — своя сцена и свой процесс рендера WebView2: нагрузка на GPU растёт с числом
  мониторов. Выключенный монитор (`off`) не стоит ничего.
- Окна создаются из потока наблюдателя (`WebviewWindowBuilder::build`), права в
  `capabilities/default.json` выданы по маске `wallpaper-*`.
- Номера «Монитор 1, 2» в настройках идут слева направо и могут не совпадать с номерами в
  параметрах экрана Windows.
