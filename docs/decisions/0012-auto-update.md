# 0012. Автообновление через релизы публичного репозитория

- Дата: 2026-11-17
- Статус: принято (репозиторий `DeskWall` становится публичным)
- Кто решил: Mark (задача), Claude (схема)

## Контекст

Mark хочет, чтобы приложение обновлялось само, когда на GitHub выходит новая версия.
Приложение должно скачивать релиз без логина. Сначала репозиторий был приватным, и план был
с отдельным публичным репозиторием выпусков. Затем Mark решил сделать публичным сам `DeskWall`
(код и так под GPL-3.0), и отдельный репозиторий стал не нужен.

## Решение

- **Релизы в самом `dreyn-dev/DeskWall`**, обычные (не pre-release). Адрес ленты:
  `https://github.com/dreyn-dev/DeskWall/releases/latest/download/latest.json`. `latest` пропускает
  pre-release, поэтому ночная сборка `nightly` приложением не подхватывается.
- **Официальный Tauri updater** (`tauri-plugin-updater`). Адрес ленты и публичный ключ лежат в
  одном месте: `plugins.updater` в `tauri.conf.json`. Переезд на другой хост (например Cloudflare
  R2) это правка адреса, код не меняется.
- **Публикует сам workflow** встроенным `GITHUB_TOKEN` с `permissions: contents: write`: свой
  токен не нужен.
- **Подпись minisign** (не подпись кода Windows). Приватный ключ лежит вне репозитория
  (`E:\Work\DeskWall-files\keys`) и в секретах GitHub; публичный зашит в приложение. Приложение
  ставит только пакеты, подписанные этим ключом.
- **Режим установки `passive`**: окно установщика с полосой прогресса без вопросов, после
  установки приложение запускается снова. Для NSIS на пользователя права администратора не нужны.
- **Версия берётся из тега** `vX.Y.Z`: workflow `release.yml` ставит её в `tauri.conf.json`,
  `Cargo.toml` и `package.json` перед сборкой. В `main` версия остаётся заглушкой.
- Артефакты обновления (`createUpdaterArtifacts`) включаются только в релизной сборке через
  `tauri.release.conf.json`. Обычная и ночная сборки не требуют ключа.

## Альтернативы

- Отдельный публичный репозиторий выпусков с токеном: рассматривали, пока код был приватным;
  после открытия репозитория лишний.
- Релизы в приватном репозитории с токеном в приложении: токен можно вытащить, отброшено.
- Свой сервер или Cloudflare R2: надёжнее, но нужен аккаунт и деньги; запасной путь (достаточно
  сменить адрес в конфиге).
- Подпись кода Windows вместо minisign: это другое (SmartScreen), updater её не заменяет.

## Последствия

- Выпуск версии: тег `vX.Y.Z` → workflow собирает, подписывает и публикует релиз в этот же
  репозиторий → приложения находят его сами. Шаги и разовая настройка: [process.md](../process.md).
- Публичный репозиторий: перед открытием проверена история на секреты и личные данные
  (запись в [log.md](../log.md)).
- Потеря приватного ключа: старые установки не смогут обновиться, придётся ставить заново.
  Ключ нужно сохранить копией в надёжном месте.
- Ночная сборка (`nightly`) остаётся для проверок, на неё приложение не обновляется.
