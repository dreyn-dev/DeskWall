# Как мы работаем

Проект долгий, работа идёт в разных тредах и сессиях. Чтобы ничего не терялось и не
приходилось пересказывать, действуют правила ниже. Они обязательны и для людей, и для Claude.

## Принципы

1. **1 модуль = 1 задача = 1 файл.** У каждого модуля свой файл в `docs/modules/`. Задача
   относится к одному модулю; если задевает несколько, итог записывается в каждый.
2. **Общее в одном месте.** Цель, статус и ссылки только в [README.md](README.md), решения
   только в `decisions/`, хронология только в [log.md](log.md). Не дублировать, а ссылаться.
3. **Итог записывается сразу.** Работа не закончена, пока не обновлены документы.
4. **Документы правдивы.** Если код и документ расходятся, исправляем документ в том же PR.

## Начало задачи

1. Прочитать [README.md](README.md), файл нужного модуля и связанные решения.
2. Посмотреть последние записи в [log.md](log.md) и открытые PR, чтобы не пересечься с другим
   тредом.
3. Создать ветку от свежего `main`.

## Конец задачи (чек-лист)

- [ ] Файл модуля: обновлены «Статус», «Что сделано», «Открытые задачи», «Известные проблемы».
- [ ] Новый модуль: создан файл по шаблону [modules/_template.md](modules/_template.md) и строка в
  таблице модулей в [README.md](README.md).
- [ ] Принято решение, которое сложно отменить (стек, лицензия, формат данных, подход к API):
  новый файл в `decisions/` по шаблону [decisions/_template.md](decisions/_template.md).
- [ ] Запись в [log.md](log.md): дата, что сделано, ссылка на PR, что дальше.
- [ ] Если поменялся этап: [roadmap.md](roadmap.md) и раздел «Текущее состояние» в README.
- [ ] Короткая сводка в память проекта Claude (`MEMORY.md`): только итог одной строкой и ссылка
  на docs, без дублирования деталей.

Документы обновляются **в том же PR**, что и код.

## Ветки, PR и мерж

- Работа в ветках, в `main` только через PR.
- Перед пушем все проверки из [AGENTS.md](../AGENTS.md) (lint, typecheck, test, e2e, cargo).
- Claude мержит **свои** PR в `main` сам, когда CI зелёный на последнем коммите (правило Mark от
  2026-11-13). Красный или незавершённый CI не мержим, чужие PR не мержим.
- После мержа `main` CI публикует установщик в релиз
  [`nightly`](https://github.com/dreyn-dev/DeskWall/releases/tag/nightly).

## Как выпустить версию

Версия приложения берётся из тега. Файлы `tauri.conf.json`, `Cargo.toml`, `package.json` вручную
менять не нужно: workflow `release.yml` подставит версию сам.

1. Убедиться, что нужные PR влиты в `main`, а CI зелёный.
2. Выбрать номер версии выше предыдущей (например `0.2.0`, формат `X.Y.Z`).
3. Поставить и отправить тег (команды дадут Claude или Mark в терминале):
   `git tag v0.2.0` и `git push origin v0.2.0`. Либо на GitHub: Actions → Release → Run workflow →
   ввести `0.2.0`.
4. Workflow соберёт установщик, подпишет его и опубликует релиз в
   [`dreyn-dev/deskwall-releases`](https://github.com/dreyn-dev/deskwall-releases/releases).
5. Установленные приложения найдут версию сами в течение 6 часов (или сразу по кнопке
   «Проверить сейчас») и обновятся. Сам процесс: [modules/updater.md](modules/updater.md).

### Разовая настройка (делает Mark, сделать за него нельзя)

1. Создать публичный репозиторий. На GitHub под аккаунтом `dreyn-dev`: «+» вверху справа → New
   repository → Owner `dreyn-dev`, имя `deskwall-releases`, Public. Поставить галочку «Add a README
   file» (пустой репозиторий не принимает релизы). Create repository.
2. Создать токен. Settings аккаунта → Developer settings → Personal access tokens →
   Fine-grained tokens → Generate new token. Имя `deskwall-releases`, срок как удобно (например
   1 год). Repository access: Only select repositories → `deskwall-releases`. Permissions →
   Repository permissions → Contents: Read and write. Generate token и скопировать его (он
   показывается один раз).
3. Открыть приватный репозиторий `DeskWall` → Settings → Secrets and variables → Actions →
   New repository secret. Добавить три секрета:
   - `RELEASES_TOKEN`: токен из шага 2.
   - `TAURI_SIGNING_PRIVATE_KEY`: полное содержимое файла
     `E:\Work\DeskWall-files\keys\deskwall-updater.key` (открыть в Блокноте, выделить всё,
     скопировать).
   - `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`: содержимое файла
     `E:\Work\DeskWall-files\keys\password.txt`.
4. Сохранить копию папки `E:\Work\DeskWall-files\keys` в надёжное место (облако с паролем,
   флешка). Если ключ потерять, уже установленные приложения перестанут обновляться.
5. Выпустить первый релиз по списку выше.
