# Модуль: Окно настроек

- **Статус:** прототип нового дизайна, оба режима остаются (решение Mark 2026-11-14): A «Окно» и
  B «Настройки сбоку экрана» (EN «Side panel»; слово «панель на рабочем столе» не используем)
- **Код:** `apps/desktop/index.html`, `apps/desktop/src/settings/` (`App.tsx` режимы A и B и
  подсказка первого запуска, `Panel.tsx` общее содержимое панели, `ui.tsx` компоненты,
  `TitleBar.tsx`, `bridge.ts` состояние и связь с хостом, `format.ts`, `i18n.ts`, `styles.css`
  токены); общее: `apps/desktop/src/shared/{themes,host}.ts`; хост: `src-tauri/src/{tray,chrome,load}.rs`
- **Связанные решения:** [ADR-0007](../decisions/0007-own-product-redesign.md),
  [ADR-0008](../decisions/0008-gradientdeck-assets.md), источник правды по стилю
  [`brand/DESIGN.md`](../../brand/DESIGN.md) v0.3
- **Обновлено:** 2026-11-16

## Назначение

Окно, где выбирают тему и настраивают её. Сохраняет настройки и рассылает их окну обоев.

## Устройство

- Один `index.html`, режим по адресу: без параметра режим A, `?mode=dock` режим B.
- **Режим A «Окно»** (окно `settings`, 1200×760, минимум 960×640, без системной рамки): живое
  превью `wallpaper.html?embed&inset=80` на всё окно в масштабе 0.75 (выглядит как рабочий стол;
  `inset` отодвигает фейковые иконки от кнопок). Справа сверху подписанные пилюли «Темы» (`T`) и
  «Настройки» (`S`) и круглая кнопка паузы превью с подсказкой; справа снизу карточка-кнопка
  «Настройки сбоку экрана» (`D`) с рисунком «экран с полосой справа» и строкой «Открыть настройки
  узкой полосой справа — видно, как меняются ваши обои». Внизу слева ярлык нагрузки «CPU 4% · GPU 9% · 30 FPS · WEBGL2» и пилюля
  с номером и именем темы. Панель 400 px справа: «Темы» прокручивает к списку тем, «Настройки» к
  «Общим»; на месте кнопок пилюля «Закрыть» с `Esc`, после закрытия фокус возвращается на «Темы».
  Клавиши по физическим клавишам (`e.code`), поэтому работают и в русской раскладке. Пока окно
  открыто и не свёрнуто, обои на рабочем столе на паузе (причина `settings`).
- **Строка заголовка** 40 px (`TitleBar.tsx`): подложка `pill` 0.75 только под знаком с именем и
  под кнопками Windows. Snap Layouts: хост (`chrome.rs`) кладёт над кнопкой «Развернуть» почти
  прозрачное дочернее окно, которое отвечает `HTTRANSPARENT`, его соседи из нашего потока тоже,
  а главное окно отвечает `HTMAXBUTTON`. Клик хост доводит сам: на нажатии захватывает мышь
  (`SetCapture`), на отпускании над кнопкой разворачивает или восстанавливает окно (Windows не
  присылает `WM_NCLBUTTONUP`, если нажатие не отдано системе: из-за этого в v2 кнопка не работала).
  Хук ставится при каждом показе окна и при фокусе. Наведение и нажатие хост присылает событием
  `deskwall://caption`, страница рисует их сама.
- **Режим B «Настройки сбоку экрана»** (окно `dock`): полоса 400 px у правого края рабочей
  области монитора под курсором (учитывает панель задач и DPI), поверх настоящих обоев, без превью.
  Заголовок «DeskWall · настройки», кнопки «Открыть большое окно» и «Закрепить». Без закрепления
  полоса прячется, только если фокус ушёл при нажатой кнопке мыши (или Alt / Win): Windows сама
  двигает фокус после закрытия меню трея и при старте, из-за этого в v2 полоса пропадала сразу.
  Первые 1,2 с после показа потеря фокуса не считается. Ярлык нагрузки показывает обои на рабочем
  столе. Esc прячет полосу.
- **Переключение:** кнопки в A и B, пункты трея «Окно настроек» / «Настройки сбоку экрана» и
  аргумент запуска `deskwall.exe --open=window|dock` (ярлыки, проверка на ПК)
  запоминают режим в `Settings.trayOpens`; клик по значку трея открывает его. То же можно выбрать
  в «Общих»: «Клик по значку в трее открывает: Окно / Панель».
- **Первый запуск** (`Settings.hintSeen = false`): хост открывает A, поверх превью карточка в
  3 шага (тема, режим панели, значок в трее) с обводкой нужной кнопки; «Пропустить» / Esc /
  «Понятно» ставят `hintSeen`. Сброс настроек её не возвращает.
- **Нагрузка** (`load.rs`, команда `load_stats`, опрос раз в 2 с только при открытой панели или
  окне): CPU по времени процессов DeskWall и всех его процессов WebView2 (доля всей машины), GPU
  по счётчикам Windows «GPU Engine» (как в диспетчере задач: сумма наших процессов по движку,
  берётся самый занятой). В браузере только FPS и бэкенд.
- Содержимое панели одинаковое (`Panel.tsx`): список тем крупным Cormorant с номерами 01–04 (Пляж, Луг, Проталины, Острова),
  описание, параметры активной темы из `shared/themes.ts`, для «Островов» палитра и пейзаж, затем
  «Общие»: тень под подписями, FPS, пауза при полном экране, автозапуск (только в приложении),
  язык (System / English), что открывает клик по значку, сброс.
- Окна держат настройки в одном store: при фокусе окно перечитывает его, поэтому A и B не
  расходятся.
- Состояния превью: «Сцена растёт» до первого кадра; ошибка темы → текст `danger` и
  «Перезапустить тему»; «Работает в режиме совместимости», если «Острова» ушли на WebGL2; «Пауза»
  в ярлыке, если превью на паузе.
- Стиль: токены DESIGN.md в `@theme` Tailwind 4, светлая и тёмная тема по Windows, `forced-colors`,
  `prefers-reduced-motion`, кольцо фокуса. Шрифты OFL из `@fontsource` (латиница и кириллица).
  Иконки lucide-react. Подсказки (`Tip`) у всех кнопок-значков.
- `i18n.ts`: словари EN и RU. В списке языков только «System» и English; русский только через
  «System» на русской Windows. Трей следует тому же правилу.

## Известные проблемы

- Подсказка у «Развернуть» не показывается: мышь над кнопкой забирает хост (вместо неё Windows
  показывает Snap Layouts).
- Закрепление панели B не сохраняется между запусками.
- В режиме A превью рисует фейковые иконки; на тёмной теме Windows сцена остаётся светлой (у сцены
  свои цвета).

## Как проверить

- Браузер: `pnpm --filter @deskwall/desktop dev` → `http://localhost:5180/` (режим A),
  `http://localhost:5180/?mode=dock` (режим B); `?renderer=webgl` для WebGL2. Подсказку первого
  запуска вернуть: удалить `deskwall.settings` из `localStorage`.
- Приложение: `pnpm tauri dev` (установленный DeskWall из `%LOCALAPPDATA%\DeskWall` должен быть
  остановлен), правый клик по значку в трее → «Окно настроек» (A) или «Настройки сбоку экрана» (B);
  или `target\debug\deskwall.exe --open=dock` при запущенном приложении.
- Тесты: `pnpm test`, `pnpm e2e` (первый запуск, A, переключение режима, B); `cargo test` (форма
  протокола, геометрия кнопки, разбор счётчиков GPU, замер CPU). На ПК Mark нет браузера
  Playwright: e2e запускать с
  `PW_CHROMIUM_PATH="C:/Program Files/Google/Chrome/Application/chrome.exe"`.
